# 10 分钟讲解提纲

这份提纲面向“已经学过一些机器学习、深度学习或大模型基础，但还没有真正做过机器人系统集成”的学生。

目标不是把所有代码讲完，而是让学生在 10 分钟内回答清楚 4 个问题：

1. 这个系统想解决什么问题
2. 为什么它不是一个端到端 policy，而是分层系统
3. 本地 `Qwen3` 在系统里的位置是什么
4. 学生回去后应该从哪里开始复现

建议讲解版本：

- branch: `release/v0.1.4`
- tag: `v0.1.4`

## 0. 先给学生的一句话定位

建议开场直接说：

“这个项目是一个基于 `ROS2 + PyBullet + 视觉感知 + 本地 Qwen3` 的机械臂 VLA 原型系统。它的目标不是让一个模型直接端到端输出关节控制，而是把语言理解、场景感知、任务规划和动作执行拆成多个可解释模块，再把它们串成一个闭环。”

## 1. 时间分配

### 第 0 到 1 分钟：讲问题

你要先回答“我们为什么要做它”。

建议说：

- 传统机器人系统通常是手工写状态机，灵活性差
- 纯端到端 VLA 又很难调试、很难稳定复现
- 所以这个系统选择中间路线：
  - 用大模型负责高层语义规划
  - 用感知模块负责目标定位
  - 用执行器负责状态机调度
  - 用控制器负责低层运动

### 第 1 到 3 分钟：讲系统架构

只讲下面这条主链：

```text
自然语言指令
  -> llm_task_planner_node
  -> /llm_task/plan_json
  -> llm_task_executor_node
  -> /sam3/prompt
  -> sam3_mask_node
  -> mask_depth_fusion_node
  -> scene_object_registry_node
  -> iiwa_keypoint_tracker_node
  -> PyBullet 机械臂执行
```

这一步只讲角色，不讲实现细节：

- planner 决定“做什么”
- executor 决定“按什么顺序做”
- perception 决定“目标在哪里”
- tracker/controller 决定“机械臂怎么过去”

### 第 3 到 5 分钟：讲 Qwen3 在哪里

这一段最重要，因为学生很容易误以为“Qwen3 = 整个系统”。

要明确讲：

- `Qwen3` 不是整个 VLA 系统
- `Qwen3` 是高层规划模块背后的推理引擎
- 它接收：
  - 用户自然语言指令
  - 场景摘要 `/scene/objects_json`
- 它输出：
  - 结构化 `plan_json`

一句话解释：

“Qwen3 在这里像机器人的高层大脑，但它不直接做视觉，也不直接输出关节控制。”

### 第 5 到 7 分钟：讲这次版本升级做了什么

这里建议围绕 `v0.1.4` 讲 4 件事：

1. planner 从只支持 OpenAI，变成支持本地 `Qwen3(vLLM)` 和 OpenAI 双后端
2. 新增 `scene_object_registry_node`，把感知结果整理成 planner 可读的场景摘要
3. executor 增加了 step 级目标确认，避免切换目标时沿用旧 keypoint
4. 新增 `staged_single_gpu` 模式，让单张 GPU 也能跑“先规划、再执行”

这一段的目标是让学生理解：

“系统的难点不只是模型接上 API，而是让它和感知执行链路衔接起来。”

### 第 7 到 8.5 分钟：讲为什么速度慢

这是学生很爱问的问题，建议你主动解释：

- 当前系统更偏“稳定闭环”而不是“最低时延”
- 单卡模式下，`Qwen3` 和 `SAM3` 要轮流占 GPU
- executor 在每步里会等待目标重新确认
- 所以延迟上升是架构选择带来的代价，不是某一个函数写得慢

这样学生会把“系统延迟”理解成工程权衡，而不是 bug。

### 第 8.5 到 10 分钟：讲怎么复现

最后不要讲一堆文件名，直接给学生一条最短路径：

1. 切到 `release/v0.1.4`
2. 构建 `pybullet_ros2_sim`
3. 用 `SIM_GUI=false + staged_single_gpu` 跑最稳的单卡版本
4. 发一条任务
5. 看 planner 状态和执行结果

建议最后一句话：

“你们复现时不要一开始就想跑完整系统，而是先验证每一层：仿真、感知、planner、executor，最后再连成闭环。”

## 2. 建议你实际讲的时候怎么说

下面是一段可以直接口述的版本。

“这个系统是一个分层式的机器人 VLA 原型。用户输入自然语言后，planner 会结合当前场景生成结构化计划；executor 再把计划变成逐步执行过程；感知模块负责持续锁定当前目标；tracker 和控制器最后把目标变成机械臂在 PyBullet 里的运动。  
这套系统的关键不在于单一模型，而在于接口设计。我们没有让一个模型直接输出低层控制，而是让 `Qwen3` 负责高层规划，感知模块负责定位，控制模块负责执行。这样做的好处是：每一层都能单独调试，也更适合教学复现。  
在当前 `v0.1.4` 版本里，我们把本地 `Qwen3` 接进了 planner，同时加入了场景注册表和单卡分阶段执行机制，所以它已经不只是一个 LLM demo，而更像一个可解释、可扩展的分层式 VLA 系统基线。”  

## 3. 课上最值得强调的 3 个概念

### 3.1 分层比端到端更适合教学复现

因为：

- 容易定位问题
- 容易替换模块
- 容易做 ablation
- 更适合学生分组协作

### 3.2 场景摘要是大模型接机器人时的关键中间接口

不要让学生只盯着“模型名字”。  
真正关键的是：你怎么把感知结果整理成 planner 能稳定消费的状态表示。

### 3.3 单卡资源调度本身也是系统设计的一部分

学生常常把“模型推理”看成独立环节，但在机器人系统里：

- 显存竞争
- 进程生命周期
- 感知和规划的时间错位

这些都会直接影响系统能不能跑起来。

## 4. 讲解结束时可以留给学生的 3 个问题

1. 如果动作集合从 `hover_target` 扩展到 `grasp/place`，应该先改哪一层？
2. 如果不用 `scene_object_registry_node`，planner 直接读原始感知 topic，会遇到什么问题？
3. 如果 GPU 更大，`staged_single_gpu` 模式是否还必要？系统会在哪些地方变快？
