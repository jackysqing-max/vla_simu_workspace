# v0.1.5 Release Notes

`v0.1.5` 是在 `v0.1.4` 的本地 Qwen3 VLA 基线之上做的一次“实机 RGB-D 接入与运行稳定性收口”版本。这个版本没有推翻原来的 planner-executor 主链，而是把它补成了更适合真实相机联调、实时可视化和单机排障的形态。

## 1. 版本定位

`v0.1.4` 的重点是：

- 本地 `Qwen3(vLLM)` 规划后端
- 单卡 staged 执行
- `scene_object_registry_node` 场景摘要
- 更稳的 step 级 prompt / tracking 衔接

`v0.1.5` 的重点则是：

- 接入真实 `RealSense D456`
- 提供独立的实时 RGB-D 关键点 pipeline
- 把 SAM3 跟踪、关键点融合、监视器显示和窗口退出逻辑打磨到可直接联调
- 给本地部署场景补上更直接的 GPU 监视工具

一句话总结：

`v0.1.5` 把 `v0.1.4` 从“本地 Qwen3 + 仿真主链可跑”推进到了“真实 RGB-D + 实时关键点可视化 + 排障更顺手”的版本。

## 2. 主要变化

### 2.1 新增 `vla_rgbd_tools` 实机 RGB-D 工具包

新增包：

- `src/vla_rgbd_tools/launch/real_rgbd_keypoint_pipeline.launch.py`
- `src/vla_rgbd_tools/vla_rgbd_tools/tracking_overlay_viewer_node.py`
- `src/vla_rgbd_tools/vla_rgbd_tools/mask_depth_to_cloud_node.py`

它们组成了一条独立于仿真主链的实机调试路径：

```text
RealSense D456
  -> /camera/camera/color/image_raw
  -> /camera/camera/aligned_depth_to_color/image_raw
sam3_mask_node
  -> /sam3/mask, /sam3/score
mask_depth_fusion_node
  -> /perception/keypoint_3d, /perception/keypoint_overlay, /perception/valid
tracking_overlay_viewer_node
  -> 本地实时可视化窗口
robot_monitor
  -> prompt / valid / keypoint 空间位置显示
```

这条路径的目标不是替代原来的 VLA planner-executor，而是让“看到真实物体、打 prompt、看关键点、看 3D 坐标”这件事可以先独立跑通。

### 2.2 `mask_depth_fusion_node` 补上 RealSense 兼容性

`v0.1.5` 中的 `mask_depth_fusion_node` 主要新增了：

- `uint16 depth -> meters` 的 `depth_scale` 转换
- 空编码但行步长有效时的深度帧兼容
- `camera_info` 改用更适合图像链路的 QoS
- 当 `target_frame == msg.header.frame_id` 时直接使用单位变换

这些改动解决的是典型实机问题：

- RealSense 深度编码和仿真深度编码不一致
- 图像和内参 QoS 不匹配时收不到 `camera_info`
- 没有外部 TF 时，关键点仍然需要落在相机光学坐标系里

### 2.3 `tracking_overlay_viewer_node` 支持真正的实时观察

这个 viewer 节点提供：

- 叠加图优先、彩色图兜底的实时显示
- prompt、score、状态、3D keypoint 文本标注
- 图像上的 2D 关键点十字标记
- 用户关闭窗口后 viewer 节点主动退出，而不是下一帧又把窗口弹回来

也就是说，`v0.1.5` 里“窗口能打开”不再是目标，“窗口能稳定反映当前 prompt 是否命中目标、关键点是否新鲜、坐标是什么”才是目标。

### 2.4 `robot_monitor` 从关节图表扩展到关键点调试

`robot_monitor` 这次增加了：

- `/sam3/prompt` 订阅
- `/perception/valid` 订阅
- `/perception/keypoint_3d` 订阅
- 状态栏实时显示 prompt、tracking 状态和关键点坐标
- 关闭窗口时联动 `rclcpp::shutdown()`
- 避免 relaunch 时的 `ParameterAlreadyDeclaredException`

这样一来，监视器不再只是看关节曲线，还能直接承担 VLA / 感知联调时的状态面板角色。

### 2.5 SAM3 与启动脚本更适合单机实际运行

`sam3_mask_node` 增加了：

- `device='cuda'` 但 CUDA 不可用时自动回退到 CPU

`start_llm_rekep_demo.sh` 增加了：

- 独立 GPU monitor window
- `gpu-monitor` / `gpu-snapshot` 命令
- 更明确的 GPU monitor 状态输出

这部分让“之前能跑、现在因为驱动或 CUDA 状态变化又跑不起来”的情况更容易定位。

## 3. 这一版对 VLA 主链意味着什么

`v0.1.5` 仍然保留 `v0.1.4` 的主链：

```text
instruction
  -> llm_task_planner_node
  -> /llm_task/plan_json
  -> llm_task_executor_node
  -> /sam3/prompt
  -> sam3_mask_node
  -> mask_depth_fusion_node
  -> iiwa_keypoint_tracker_node
```

但它额外补上了一条“更像实验台”的旁路：

- 实机 RGB-D 输入
- 关键点叠加可视化
- 关键点空间位置打印
- GPU 占用观察

所以从研发流程看，`v0.1.5` 的价值在于把“高层规划链路”和“底层真实感知联调”拆成了两条都能独立验证的路径。

## 4. 适用场景

`v0.1.5` 更适合：

- 用 `RealSense D456` 直接看真实物体关键点
- 现场调 prompt 是否命中目标
- 快速判断 `valid=false` 是 SAM3、深度、QoS 还是 TF 问题
- 在单卡机器上观察 Qwen3 / SAM3 的资源占用

## 5. 已知边界

这个版本已经能更稳地跑实机关键点链路，但它仍然有明确边界：

- prompt 命中质量仍然决定 SAM3 是否能锁定真实目标
- 没有外部标定时，关键点默认落在相机光学坐标系
- Qwen3 仍然是高层语言规划器，不是端到端视觉策略
- 实机链路稳定后，还需要再把 tracker 和真实机械臂闭环彻底接上
